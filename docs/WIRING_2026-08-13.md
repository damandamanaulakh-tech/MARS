## New module: `trading/external_panels.py`

One batch loader per trigger-layer run, because the delivery file is 3.5M
rows and a per-stock pass would be 80 passes over it. It builds, from
committed files only and with no network call:

* an equal-weight **sector index** and **peer breadth** series per sector,
  from the 191×12y OHLCV panel grouped by the 191-name / 19-sector map in
  `trading/universes.py`
* cross-sectional **rank** populations (relative strength, turnover) plus a
  **within-industry** rank, which is what the owner's "industry_relative_rank"
  actually means
* per-stock **delivery ratio**, **F&O open interest**, and **bulk/block deal**
  windows anchored to that stock's own as-of bar

Two bugs the real data exposed while wiring, both fixed before commit:

1. **The deal window was anchored to each symbol's last-ever deal**, so any
   name with a deal anywhere in its history read "recent deal" forever — every
   stock fired both deal triggers. Now anchored to the stock's own as-of bar.
2. **Both deal triggers fired together** even after that fix, because NSE
   reports both counterparties of a block deal. Direction now comes from bulk
   rows only (per-client disclosures); block deals are carried as presence.

## Honesty rules kept

* **No panel, no reading.** Every field is optional; a missing file, an absent
  symbol or too little history returns `None`, which stays DATA_NEEDED on
  screen. A quiet `False` would read as "computed, nothing there" — that is
  the fake-data failure mode the owner banned, and
  `trading/tests/test_external_panels.py` pins it for all 21 triggers.
* **Nothing changed on the no-panel path.** `evaluate(df)` without panels
  returns exactly what it did before, so the previously-shipped behaviour is
  untouched and testable side by side.
* **Every reading carries its as-of date.** The committed OHLCV panel ends
  before today (2026-07-17 at the time of writing) while the index file runs
  to 2026-08-07 and the deal files to 2026-08-04. Relative-strength numbers
  are as-of the panel, and the page says so instead of implying "live".
* **Proxies are labelled as proxies.** X-06 is public shareholding %, not true
  free float (which excludes locked-in public holdings). W-022 is a put/call
  ratio on **open interest**, not on volume — the register asked for volume,
  and the volume version needs an options chain we do not have.
* **Assumed constants are collected, not buried.** Where the owner's sheet
  says "threshold" or "improves", the number sits in
  `external_panels.ASSUMED_EXTERNAL_CONSTANTS` for their calibration run
  (BT06) to replace with a measured value, exactly like the OHLCV side.

# Recalibration: T12W_0066 gap-up rejection (owner order, same day)

Owner: *"wire 0066 with gap 1%"* — after the threshold sweep showed the
rejection was the constant's fault, not the rule's.

**What changed.** The rule was `open > prior_high AND close < open AND volume >
1.5x vol20`. The gap size was unconstrained, so an open one paisa above
yesterday's high counted as a gap. It now requires the gap to be **at least
1%** (`MEASURED_CONSTANTS["gap_up_min_gap"]`). The volume multiple is
unchanged at 1.5x — the order named the gap only.

**What it bought, measured on the owner's own 191x12y panel:**

| | fires | hit rate | chance | lift | verdict |
|---|---|---|---|---|---|
| before (gap unconstrained) | 964 | 21.27% | 19.49% | 1.091 | REJECTED |
| after (gap >= 1%) | 347 | 23.63% | 19.49% | **1.213** | SUPPORTED |

Split-sample, which is the number that matters: **train 1.217 (2014-2020),
test 1.227 (2020-2026)**. The two halves agree, and the whole surface improved
monotonically with gap size at every volume multiple — 1.06 → 1.17 → 1.23 →
1.58 as the gap requirement rose 0% → 0.5% → 1% → 2%. A monotone gradient is an
effect; a single good cell would have been noise. Median lead time 2 days,
false-positive rate 30.6%.

A higher-lift setting existed (gap >= 2%, test lift 1.58) but on 104 fires; the
owner's 1% sits on 217 test fires with a stabler train/test pair.

**Why the stored verdict had to be replaced.** `CALIBRATION` is loaded from the
2026-08-09 run, which measured the OLD rule. Leaving 1.091/REJECTED on screen
next to a rule that no longer matches it would misreport the live trigger, so
`RECALIBRATED` carries the new numbers, names the sweep that produced them, and
keeps the superseded verdict visible as history.

**Measured is not assumed.** The new number lives in `MEASURED_CONSTANTS` with
its provenance in `MEASURED_CONSTANT_SOURCE`, separate from
`ASSUMED_CONSTANTS`, so the page can say which constants were measured and
which are still placeholders. A test asserts it is not filed as assumed.

**Scope.** T12W_0066 is display and watchlist only; a test asserts it is NOT in
`danger.VERIFIED`, so this did not touch the money path. The three
sweep-survivors that were NOT ordered (T12W_0040 oversold-to-neutral, test lift
1.48 at RSI 25 -> 50, and T12W_0005 inside-bar cluster, 1.12 at 7-in-15) are
left exactly as they are.

# Recalibration: T12W_0040 oversold-to-neutral (owner order, same day)

Owner: *"wire 0040 too"*.

**A correction first, because it changes which number is real.** I had told the
owner this trigger "measured 1.48 test lift at RSI 25 -> 50". That was the best
cell **on the test half** — and reading the holdout to choose a setting
destroys the holdout. In training, that same setting scored **1.096**, below
the 1.10 bar; it would never have been selected. The clean number is the one
from the setting the split-sample protocol actually chose on training data:

| setting | train | test | fires (all) |
|---|---|---|---|
| RSI < 35 -> 45 (before) | 1.023 | 1.094 | 6,143 |
| **RSI < 30 -> 45 (now)** | **1.162** | **1.142** | **2,985** |
| RSI < 25 -> 50 (the tempting cell) | 1.096 | 1.482 | 723 |

**What changed.** The entry depth only: RSI must dip below **30**, not 35. The
rule was `min(RSI[-6:-1]) < 35 AND RSI[-1] > 45`.

**What was deliberately NOT changed.** The exit level stays at 45. Training
preferred 45, the test half preferred 50 — the two halves disagree on that
axis, so it is not a measured quantity and fitting it would be curve-fitting.
`MEASURED_CONSTANT_SOURCE["oversold_exit_rsi"]` says exactly that, and a test
asserts the note still says it.

**What is structural, and why the entry depth is trustworthy.** In BOTH halves,
lo=25 and lo=30 beat lo=35 and lo=40 at every exit level. "A shallow dip is not
an oversold" holds independently in each half — that is a property of the data,
not a fitted cell. Full lift surface: `research/threshold_sweep/`.

Post-change: 2,985 fires, 133 hits, 4.46% vs a 3.84% chance rate = lift 1.161,
REJECTED -> SUPPORTED. Median lead 4 days, false-positive rate 31.9%.

**Scope.** Display and watchlist only; a test asserts T12W_0040 is not in
`danger.VERIFIED`. The stored 1.065/REJECTED verdict is replaced by the
recalibrated one with the superseded value kept as history, same as 0066.

## THE EVIDENCE BARS ARE NOT THE SAME, AND THAT IS DELIBERATELY VISIBLE

The 10 incumbent tripwires cleared VERIFIED at the **strict** labels
(+/-15% moves). The external calibration was only produced at the **main**
labels (+/-10%), so these two cleared the **lower** bar. Rather than smooth
that over:

* every entry carries a `labels` field (`"strict +/-15%"` vs `"main +/-10%"`),
* `describe()` prints it, so it lands in the journal and the phone alert,
* the DANGER_LAYER_ARMED journal line states how many are panel-fed and which
  bar each group cleared,
* a test asserts the two groups stay distinguishable.

Re-running the external calibration at strict labels would settle whether they
hold to the incumbent standard. Until that runs, this difference is stated, not
hidden.

## Design facts worth keeping

**They are mutually exclusive.** 0095 requires the held name's support to be
BROKEN; 0094 requires it INTACT (peers fall first, the target still holding).
So the pair can never both fire on the same day, which means **on their own
they can only ever tighten a stop, never reach the 2-fire EXIT_HALF rung**.
They can still combine with an OHLCV tripwire to get there. Test-pinned.

**A future run cannot self-promote.** `_EXTERNAL_ALLOWED` names the two ordered
ids, so a later external calibration scoring something VERIFIED does not put it
in the money path — that still takes an owner order. Test-pinned.

**Panels are loaded light and fail safe.** `danger.externals_for()` requests
only the peer panel and the index — never delivery, F&O or deals — because it
runs inside `engine.refresh`, where streaming a 3.5M-row file would be
unacceptable (1.5s vs ~8s). Any failure returns None, the two tripwires
abstain, the other 10 still run, and a `DANGER_PANELS_UNAVAILABLE` journal line
fires once a day so a silent loss of cover is visible.

**The boundary held.** `engine.py` still contains no reference to
`external_panels`; it reaches the panels only through `trading/danger.py`. The
module docstring now says the scope changed — it is no longer display-only —
because claiming otherwise would be false. Test-pinned in both places.

Danger layer now: **12 tripwires** (10 OHLCV strict-label + 2 panel-fed
main-label) guarding held names.

# News feed — built on the owner's design (2026-08-14)

Owner: *"put algorithm on rss feed"* → their design: *"when i will fetch new
universe for stocks, u will run the feed that time only and it kept on that
stock ... if it value it trigger or it pass"* → scope: **"no block just show"**.

Their design was simpler and better than the twice-weekly schedule I proposed:
one pass per daily cycle over the names the scan already filtered, verdict
stuck to the stock, read TRIGGER or PASS.

## What it does

`trading/news_feed.py` fetches each name's Google News RSS (7 days, which is
all Google serves), keeps only headlines that **actually name the stock**, tags
events by deterministic keyword rules, scores lexicon sentiment on the
untagged ones, and returns TRIGGER / PASS / NO_NEWS / UNKNOWN per stock.

`web/scheduler.run_news_feed` runs it right after the trigger layer — the same
daily cycle that follows the 09:20 scan, never on a schedule of its own — over
held names first, then picks, then the scanned bucket, capped at 60. The result
persists in `portfolio.news_watch` (JSON **and** the Mongo mirror, both
directions — the risk_day lesson). A crash there cannot touch the scan or the
trigger-layer result just computed.

## No LLM, on purpose

The owner's API keys are available, but the verdict is rule-based. An LLM
verdict is unreproducible and unauditable — you cannot point at the phrase that
caused it, and the same headline can score differently twice. The rules cover
the events their sheet names (results beat/miss, order win, regulatory,
governance, rating change, expansion, block deal, rumour), and every tag can be
explained by the matched phrase. A test asserts no LLM library is referenced.

## Three faults found against the LIVE feed, all fixed

1. **A false positive that would have flagged a bank.** An RBI headline about
   *"AI ... fraud detection in banking"* matched the fraud pattern and tagged
   YESBANK as a governance risk — enough, alone, to read TRIGGER. Fixed with a
   negative lookahead (`fraud` not followed by detection/prevention/management),
   and then fixed at the root: **headlines must name the stock**, and that RBI
   headline never mentioned the bank at all. Google News answers a company query
   with sector round-ups, so without that filter one company's event is
   attributed to another.
2. **A false negative in the same stock.** *"Yes Bank Senior Group President
   Rajat Monga Quits"* was MISSED because the pattern only knew CFO and CEO.
   Now any senior role (MD, chairman, president, whole-time director, company
   secretary…) quitting or exiting tags as governance.
3. **Quote pages drowning the real news.** RELIANCE's top three "headlines"
   were a live-price page, a chart page and a weekly-outlook template. Those
   describe nothing that happened, so they are dropped as noise.

Also: `bags Rs 2,400 crore order` needed gap-tolerant patterns — Indian
headlines put the deal size between the verb and the noun.

## Honesty properties, test-pinned (22 tests, offline and instant)

* **UNKNOWN ≠ NO_NEWS.** A failed fetch reads UNKNOWN with `fetch_failed`, and
  the page shows FETCH FAILED. "The fetch broke" and "there is no news" are
  different facts and must never render as the same chip. Google News 503s
  intermittently, so the fetcher retries three times first.
* **Nothing can block a buy.** A test asserts `engine.py`, `risk.py`,
  `orders.py` and `danger.py` never import this module. The reason is recorded
  in the module docstring: no news archive is reachable, so a news rule can
  never be calibrated, and the owner's own REQUIRES_15Y_BACKTEST rule keeps it
  out of the money path. The page repeats it: *display only — a news verdict
  never blocks a buy or moves a stop*.
* **The classifier is pure** — no network, no clock, no model. Same headline,
  same verdict, five times over, asserted.
* **Sentiment is not double counted**: a headline with an event tag carries its
  event weight and no lexicon score.
* `TRIGGER_SCORE` and the event weights are **ASSUMED** and say so — no
  calibration exists for news and none can.
