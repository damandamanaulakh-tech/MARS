## New module: `trading/external_panels.py`

One batch loader per trigger-layer run, because the delivery file is 3.5M
rows and a per-stock pass would be 80 passes over it. It builds, from
committed files only and with no network call:

* an equal-weight **sector index** and **peer breadth** series per sector,
  from the 191×12y OHLCV panel grouped by the 191-name / 19-sector map in
  `trading/universes.py`
* cross-sectional **rank** populations (relative strength, turnover) plus a
  **within-industry** rank, which is what the owner's "industry_relative_rank"
  actually means
* per-stock **delivery ratio**, **F&O open interest**, and **bulk/block deal**
  windows anchored to that stock's own as-of bar

Two bugs the real data exposed while wiring, both fixed before commit:

1. **The deal window was anchored to each symbol's last-ever deal**, so any
   name with a deal anywhere in its history read "recent deal" forever — every
   stock fired both deal triggers. Now anchored to the stock's own as-of bar.
2. **Both deal triggers fired together** even after that fix, because NSE
   reports both counterparties of a block deal. Direction now comes from bulk
   rows only (per-client disclosures); block deals are carried as presence.

## Honesty rules kept

* **No panel, no reading.** Every field is optional; a missing file, an absent
  symbol or too little history returns `None`, which stays DATA_NEEDED on
  screen. A quiet `False` would read as "computed, nothing there" — that is
  the fake-data failure mode the owner banned, and
  `trading/tests/test_external_panels.py` pins it for all 21 triggers.
* **Nothing changed on the no-panel path.** `evaluate(df)` without panels
  returns exactly what it did before, so the previously-shipped behaviour is
  untouched and testable side by side.
* **Every reading carries its as-of date.** The committed OHLCV panel ends
  before today (2026-07-17 at the time of writing) while the index file runs
  to 2026-08-07 and the deal files to 2026-08-04. Relative-strength numbers
  are as-of the panel, and the page says so instead of implying "live".
* **Proxies are labelled as proxies.** X-06 is public shareholding %, not true
  free float (which excludes locked-in public holdings). W-022 is a put/call
  ratio on **open interest**, not on volume — the register asked for volume,
  and the volume version needs an options chain we do not have.
* **Assumed constants are collected, not buried.** Where the owner's sheet
  says "threshold" or "improves", the number sits in
  `external_panels.ASSUMED_EXTERNAL_CONSTANTS` for their calibration run
  (BT06) to replace with a measured value, exactly like the OHLCV side.

## Boundary, test-enforced

`trading/engine.py`, `risk.py` and `orders.py` must never import
`external_panels`, and the module itself contains no order call and no network
call. Both are asserted by source inspection in
`trading/tests/test_external_panels.py`, matching the existing guards on
`triggers.py` and `lens_v2.py`.

## Found while working (pre-existing, fixed)

`web/tests/test_trigger_page.py` seeded a pick with no `score` and restored
the attribute in a `finally` — but `run_trigger_layer` had already **persisted**
the portfolio, so the score-less pick stayed in `cfg.state_dir/portfolio.json`
for every later test and later run to load. `/scan` then raised
`UndefinedError` rendering it, which is a **500 on the page the owner places
orders from**. Two fixes: the fixture now saves after restoring, and the
scan template renders a missing score as "—" instead of crashing (never as a
made-up 0).
