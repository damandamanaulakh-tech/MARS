## 3. THE MONEY PATH — every rule that decides a buy or sell (plain formulas)

ENTRY (all must pass, in this order, momentum mode):
1. Universe: today's ~50-name stride slice of the full NSE list + all held
   names; YESBANK.NS blocklisted; liquidity floor = median daily turnover
   ≥ ₹1 Cr (fail-closed: missing data = no).
2. Regime: PANIC (Nifty ≤ −10% off 52w high AND VIX > 25) blocks all
   entries. CORRECTION (Nifty < 200DMA) no longer blocks (your 2026-08-09
   order); dead regime feed = keep last brake (fail-safe).
3. Momentum score ≥ 62 — score = rank-blend of 6-month and 12-month
   volatility-adjusted returns (return ÷ its own σ, cross-sectional
   percentile rank, 50/50 blend of the two windows) blended 65/35 with the
   quality score.
4. Absolute momentum: the stock's OWN 6-month return must be > 0.
5. Breadth gate: share of today's scan panel above their own 200DMA must
   be > 50% (sample ≥ 30 names, fail-open when thinner). VIX-crush
   re-entry bypasses this gate.
6. Timing: daily candle confirmation (one of the 6 strong bullish
   multi-bar structures) can accelerate entry; volume expansion lane.
7. Binary-event halt: no entries within 3 days of a real listed event.
8. risk.can_open: cash ≥ notional; regime cash reserve (0% base, 20%
   correction, 40% panic); sector cap (count + capital share);
   correlation vs held names ≤ 0.85 (computed on real aligned returns);
   portfolio heat cap; min position value ₹25k; kill switch not tripped.
9. Size: FIXED ₹1.25,000 per trade (your number) × IFR throttle (halves
   size while market internals are fractured) × drawdown-governor tier.
   Fill at live quote when the broker answers; prev-close fallback is
   journaled with fill_source.

EXIT (checked every refresh, per held stock):
1. DANGER LAYER (NEW, your order): 10 calibration-VERIFIED tripwires.
   Alert-week now; from day 8: 1 fire → stop = live price × 0.975 (never
   loosened), 2+ fires → sell half at market. Sell side only.
2. Hard stop −5% (your order) · target +12% (your choice) · trailing −15%
   (mathematically unreachable at −5/+12 — disclosed on Settings) ·
   score-decay < 50 (never on owner_pick positions) · max-hold 200
   sessions · intraday tag squared off 15:25 always.
3. Kill switch: day loss ≤ −2% from today's baseline → close what has live
   quotes, halt entries; baseline re-rolls daily; persists restarts.
4. No live quote = NO exit decision on that name (EXIT_HELD_NO_QUOTE) —
   never a fabricated fill.

OWNER DESK: BUY buttons on every listed stock; order ticket with qty /
market / limit / stop% / target%; limit orders rest till day end; SELL +
price box on positions (never deletes trades); every action journaled.

## 7. FLAWS — the honest list (new findings first)

**F1 (NEW, found in this audit): the weekly data pull skips itself.**
`_weekly_history_topup` (Friday 16:30) refuses to run without a connected
Upstox broker — but the candles it fetches come from Upstox's HISTORICAL
endpoint, which is PUBLIC (proven 2026-08-09, no token). Your token dies
every morning at 03:30, so unless you happened to log in on a Friday and
the token survived to 16:30, the job journals DATA_REFRESH_SKIPPED week
after week. This is very likely the truth behind "auto weekly new pull is
not there". Fix = drop the token gate / fetch tokenless (Node 2).

**F2: the offline Nifty-200 benchmark is committed but unused.** The
backtest still fetches ^CNX200 from Yahoo live (unreliable from cloud)
while data/nifty200_daily.csv (2004→now) sits unconsumed. Fix in Node 3.

**F3: breadth gate runs on a ±7pp noisy sample.** The gate decides on the
day's ~50-name bucket; full-panel breadth is 50.8% — the sample flips
around the 50% line day to day. Options: compute breadth on the full
stored panel instead of the bucket (exact, cheap — Node 5), or lower the
line, or toggle the gate off (Settings).

**F4: two overlapping defence systems.** IFR throttle (halves NEW entry
size on market-wide fracture) and the danger layer (defends HELD names)
are complementary — but the damage-cluster idea appears in both, and the
FII-08/09 stacks on /register use the same tail metric again. Not a bug;
worth one consolidation pass so one number drives all three (Node 9).

**F5: /register market panel is capped at 50 members, 320 bars** (512MB
RAM guard). PX/breadth numbers there are panel-relative, not full-market.
Disclosed on page; a nightly precompute could lift the cap (Node 10).

**F6 (standing, deferred by you): entry scores and exit decay use two
different rulers** (momentum blend enters; AM07 composite decays) ·
partial_profit 0.07 has no consumer · trail −15 unreachable at −5/+12
(the exit study showed +20% target with live trail beat +12 in all 4
windows — closed by your word, one word reopens) · engine.scan/refresh
and web/scheduler have no direct unit tests (integration-tested only) ·
short_interest component stubbed at 50 (5% weight) — the F&O OI panel now
in repo could replace it (Node 7).

**F7: DII data ends 2025-03 everywhere** (NSDL DII archive is OTP-walled;
NSE API gives today only). No engine path consumes DII, so this blocks
nothing — but FII-03 divergence shows DATA_NEEDED for want of a 5-day DII
history. Live scan days DO capture today's DII via the NSE API when it
answers from cloud.

**F8: token-dependent moments.** 09:20 scan prices, 15:25 square-off
prices and the (fixable) weekly top-up all degrade to fallbacks without
your morning login. Fail-visible everywhere (DATA_STALE / SKIPPED), but
the single manual act remains the app's biggest operational dependency.
