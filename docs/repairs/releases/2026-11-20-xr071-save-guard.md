# XR-071 — entry authority follows acknowledged portfolio saves

Owner authorization, 20 November 2026: stop new buys when a portfolio save
fails, keep protective exits and retries working, resume only after a confirmed
save, test and update the repository/workflow without skipping checks.

Baseline: `36ffb58ccbebe3dd334db9677484fcd7049f3293` (PR226). The live
functional predecessor is PR225 `87285df71a7cebe6b62c01636aac0eaef5afcd9b`.
This is the bounded G5/XR-071 repair. XR-069/XR-070, conflicting recovery books,
prior-process RAM gaps, off-device backups and permanent retention are separate.

## Failure and resulting behavior

The baseline only halted scheduled entries when Mongo was disconnected.
Connected quota errors left `mongo_degraded()` false; owner buys and pyramid
additions had no common save gate. Policy-read and local-save failures escaped
the Mongo error indicator. The backup route reported success after `False`.

| Path / condition | Behavior and evidence |
|---|---|
| Quota refusal, unacknowledged write, unavailable Mongo | Explicit degraded state and `portfolio_save_*` entry reason; connection success does not clear it |
| Policy read or local JSON checkpoint failure | Current book latches failure; exceptions return a failed checkpoint so exit loops and retries can continue |
| Automatic scans | Intraday, momentum, short, swing and positional picks report the save gate; funding rotation does not sell a holding for a blocked buy |
| Owner market / Buy Desk / resting limits | Common final booking guard; a limit retains its open instruction for retry or ordinary expiry |
| Pyramid additions | Guard checked before cash/quantity mutation; no increase during failure |
| Slow work / concurrent checkpoint | Recheck after target/fee work; shared reentrant book lock serializes booking and complete checkpoint acknowledgement |
| Protective exits | Stop, target, trailing and overdue intraday recovery remain independent; original segment/protection and unfinished quote work remain intact |
| Recovery / restart | Only an acknowledged current default-book save clears a failure; a new process starts unconfirmed, an unrelated portfolio write cannot clear it; failed/missing recovered-book reads or conflicting fresh holdings remain blocked without overwriting Mongo |
| Save retry | Independent 60-second job, including empty books and outside market hours; defers behind existing mode work; does not scan, quote or trade |
| Spill and forward outbox | Retain unacknowledged work; retry connected quota spills, stable event IDs, at most one 100-row archive batch per pass; forward export follows portfolio acknowledgement |
| Owner evidence | Health includes block reason and confirmation time; dashboard says buys paused and exits active; Backup Now reports false acknowledgement as failure and distinguishes local-only saves |

The first reproduction ran ten targeted cases against the baseline: **nine
failed, one passed**. Failure cases include continued eligibility, policy-read
invisibility, an unrelated save clearing the error, late failure before debit,
owner/limit bypass, false backup success, absent connected-quota retry, and a
local exception escaping the exit-safe checkpoint. The existing forward outbox
retention case already passed and is retained.
